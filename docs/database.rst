Surface Database
================

Every subject in pycortex is built around the same handful of pieces:
:term:`fiducial <fiducial surface>`, :term:`inflated <inflated surface>`,
and :term:`flat <flat surface / flatmap>` surfaces (see
:ref:`minimal-filestore-contents` for which of them a subject actually
needs), one or more functional-to-anatomical
:doc:`transforms <transforms>`, masks
derived from those transforms, and ROI/sulcus overlays. Pycortex keeps all
of this in its own **filestore** rather than reading FreeSurfer's
``SUBJECTS_DIR`` directly, because most of these artifacts (cut/flattened
surfaces, caches for the WebGL viewer, masks, ``overlays.svg``) are
pycortex-specific and have no equivalent in a plain FreeSurfer subject
directory — they're generated by, and only meaningful to, pycortex.
Centralizing them under one subject-keyed directory structure is what lets
functions across the codebase find "the fiducial surface for S1" or "the
fullhead transform for S1" by name, without every caller having to know
file layout details.

This page documents that filestore layout. If you just want to know *which*
function to call for a given task, see :doc:`overview`.

Pycortex creates and maintains a simple flat-file database store all the data required to plot data on a cortical sheet (surfaces, transforms, masks, regions-of-interest, etc.). By default, the filestore is in ``INSTALL_DATA/share/pycortex/``. This location can be customized in your ``options.cfg`` file. You can find the filestore directory by running::

    import cortex
    cortex.database.default_filestore

Within the filestore, each subject has their own directory containing all associated data.

Minimum contents for a usable subject
--------------------------------------

Most of what's documented below (the cache, ``overlays.svg``, surface
info, views) is optional or generated on demand — you don't need any of
it to get a subject working. What a subject actually needs before you
can plot data on their surface is just:

* **Surfaces**, for both hemispheres, all sharing the same vertices (see
  :ref:`database-surfaces`):

  * ``fiducial``, or the ``wm`` and ``pia`` surfaces it is computed from.
    Line-sampling mappers and the ``cortical`` mask need ``wm`` and ``pia``
    themselves.
  * ``inflated`` for the interactive WebGL viewer.
  * ``flat`` only if you want flatmaps. Without it, pycortex works fine for
    3D visualization; there is no error at import time, just a failure the
    moment something tries to flatten.

* **A transform**: at least one :ref:`transform directory
  <database-transforms>` (``matrices.xfm`` + ``reference.nii.gz``) —
  one per functional dataset you intend to align and plot, not one per
  subject.

How those files get produced is up to you. :doc:`importing_other_software`
covers FreeSurfer and other tools, but pycortex doesn't check where
the files came from — any process (a different segmentation tool, a
transform computed by your own preprocessing pipeline) that leaves
correctly-formatted files in these locations works just as well.


.. _database-access:

Browsing the database
---------------------

``cortex.db`` is the entry point to the filestore. Each kind of data has a
``get_*`` function::

    import cortex
    pts, polys = cortex.db.get_surf('S1', 'fiducial', merge=True)
    xfm = cortex.db.get_xfm('S1', 'fullhead')            # a cortex.xfm.Transform
    mask = cortex.db.get_mask('S1', 'fullhead', 'thick')  # boolean (z, y, x) array
    curv = cortex.db.get_surfinfo('S1', 'curvature')      # a cortex.Vertex

``get_surf`` returns ``(left, right)``, each a ``(pts, polys)`` pair, for
both hemispheres. With ``merge=True`` the hemispheres are stacked **left,
then right** into one ``(pts, polys)``, with the right hemisphere's polygon
indices shifted to match; with ``hemisphere='lh'`` or ``'rh'`` only that
hemisphere's ``(pts, polys)`` is returned. If a subject has no ``fiducial``
surface file, ``get_surf`` returns the average of ``wm`` and ``pia``.

``get_xfm`` returns the ``coord`` representation by default; pass
``xfmtype='magnet'`` for the other one (see :doc:`transforms`). See
:doc:`masks` for the mask types and :ref:`database-surfinfo` for
the available surface info.

The same data can be browsed through attributes, which supports tab
completion in ipython_::

    In [1]: cortex.db
    Out[1]:
    Pycortex database
      Subjects:
       S1

    In [2]: cortex.db.S1.surfaces
    Out[2]: Surfaces: [flat, wm, pia, inflated]

    In [3]: left, right = cortex.db.S1.surfaces.inflated.get()

    In [4]: cortex.db.S1.transforms
    Out[4]:
    Available transforms for S1:
    fullhead
    retinotopy

    In [5]: cortex.db.S1.transforms.fullhead
    Out[5]: Types: coord, magnet

    In [6]: cortex.db.S1.transforms.fullhead.coord.xfm   # the 4x4 matrix
    In [7]: cortex.db.S1.transforms.fullhead.masks['thick']

Attribute access only works for names that are valid Python identifiers,
so a subject called ``S1-test`` cannot be reached as ``cortex.db.S1-test``.
Every level also supports item access, which works for any name::

    cortex.db['S1-test'].surfaces['flat'].get()
    cortex.db['S1-test'].transforms['fullhead']['coord'].xfm

You can also test for a subject with ``'S1-test' in cortex.db`` and iterate
over the subject names with ``for subject in cortex.db``.


Anatomical scans
----------------

``anatomicals/raw.nii.gz`` is the subject's T1-weighted anatomical scan
(``import_subj`` copies it from FreeSurfer's ``mri/T1.mgz``). It isn't
needed to plot data, but FSL-based alignment (``cortex.align.automatic_fsl``,
``autotweak``), MNI transforms and some volume utilities read it. Other
anatomical volumes (``brainmask``, ``whitematter``, …) are generated from it
on demand by ``cortex.db.get_anat`` and saved next to it.


Cache
-----

``cache/`` holds files pycortex generates on demand and can always
regenerate: volume-to-surface mappers, flatmap pixel maps, compressed
surfaces for the WebGL viewer, and more. They are safe to delete. Most
functions take ``recache=True`` to rebuild what they use, and
``cortex.db.clear_cache(subject)`` deletes them all. The ``cache`` option
in ``options.cfg`` moves caches out of the filestore, e.g. to fast local
storage.


.. _database-surfaces:

Surfaces
--------

Surfaces are triangular meshes, one file per surface type and hemisphere,
stored in ``surfaces/`` as ``{type}_{hemi}.gii`` (``hemi`` is ``lh`` or
``rh``). GIFTI is what pycortex's importers write; ``.npz`` (keys ``pts``
and ``polys``), ``.vtk``, ``.off`` and ``.stl`` files are read too. The
types pycortex uses are:

* ``wm`` and ``pia``: the white matter and pial boundaries of the cortical
  sheet.
* ``fiducial``: the :term:`undistorted surface <fiducial surface>` in
  anatomical space. If there is no ``fiducial`` file, ``get_surf`` returns
  the average of ``wm`` and ``pia``.
* ``inflated``: the :term:`smoothed-out surface <inflated surface>` used
  by the WebGL viewer.
* ``flat``: the :term:`cut and flattened surface <flat surface / flatmap>`.

All surface types of a hemisphere must have the same vertices in the same
order: vertex *i* of the flat surface is vertex *i* of the fiducial
surface. This correspondence is what lets data mapped onto one surface be
shown on all the others. FreeSurfer surfaces have it, but pycortex does not
check it, and mismatched surfaces break in unexpected ways.

See :ref:`database-freesurfer-import` for importing a subject from
FreeSurfer and :doc:`flattening` for flattening its surfaces. To add a surface by hand, copy it into
``{filestore}/{subject}/surfaces/`` with the name above. ``get_surf`` finds
it immediately; the attribute interface (``cortex.db.S1.surfaces``) only
after restarting Python.


.. _database-transforms:

Transforms
----------

Each transform has its own subdirectory, ``transforms/{name}/``, holding
``matrices.xfm`` (the transform itself), ``reference.nii.gz`` (the
functional reference volume it was computed against) and any cached
``mask_{type}.nii.gz`` files. See :doc:`transforms` for what a transform
stores and how to add one, and :doc:`masks` for the masks.


.. _database-surfinfo:

Surface info
------------

The filestore also manages several important quantifications about the surfaces. These include Tissot's Indicatrix and the flatmap surface distortion. There are stored in the ``/surface-info`` directory. This is also where the per-vertex curvature, sulcal depth and thickness imported from Freesurfer_ are stored (see :ref:`database-freesurfer-import`). Each file is an ``.npz`` file holding one array per hemisphere, under the keys ``left`` and ``right``, and can be loaded with ``cortex.db.get_surfinfo``.

Two of them cannot be returned as a ``Vertex`` object, because that conversion concatenates arrays stored under the keys ``left`` and ``right`` and assumes one value per vertex. ``bumpy_flatmap.npz`` holds the bumpy flatmap's relief (see :class:`cortex.polyutils.FlatSlab`) as a three-component offset per vertex, of which only the third is nonzero, under the keys ``bump_left`` and ``bump_right``, and ``equivolume_areas.npz`` holds four scalar maps rather than two -- the white matter and pial vertex areas the webgl viewer's equivolume depth sampling needs -- under ``wm_left``, ``wm_right``, ``pia_left`` and ``pia_right``. For these, ``cortex.db.get_surfinfo`` hands back the ``.npz`` file itself rather than a ``Vertex``; remember to close it.

Anything computed from the flatmap -- the distortion maps, the flatmap border and the bumpy flatmap -- is deleted and regenerated when a new flatmap is imported with ``cortex.freesurfer.import_flat``, since it describes a flatmap that no longer exists.


Views
-----

``views/`` holds saved WebGL camera views, one JSON file per name. Save the
current view of an open viewer, and apply a saved one, with::

    viewer = cortex.webgl.show(volume)
    viewer.save_view(subject, name)
    viewer.get_view(subject, name)

See :doc:`features/camera_views_animations` for the default views, views
saved in the browser, and animations.


.. _database-overlays:

``overlays.svg``
----------------

``overlays.svg`` holds the subject's ROIs and sulci, as layers of an SVG
drawn on the flatmap. Surface ROIs don't depend on a transform, so there is
one file per subject. It is created the first time it's needed and edited
in Inkscape; see :doc:`rois`. Importing a new flatmap deletes it (see
:doc:`flattening`). Older subjects may have a ``rois.svg`` instead, which
is converted to ``overlays.svg`` on first use.
