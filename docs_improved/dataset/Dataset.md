## Issues with current documentation
- **`__init__`'s own docstring is essentially empty** — the class docstring says data
  objects are added via `**kwargs`, but doesn't document what each accepted value type
  (`Dataview`, `dict`, `str`, `tuple`, or another `Dataset`) actually means concretely: a
  `str` is loaded as an HDF5 file path (via `Dataset.from_file`... actually via the
  module-level `normalize()` function, not `from_file` directly — see below); a `dict` is
  itself turned into a nested `Dataset`; a `tuple` is passed through
  `cortex.dataset.views.normalize` (2-tuple → `Vertex`, 3-tuple → `Volume` or `VolumeRGB`
  depending on dtype); none of this is spelled out.
- **`append`, `__getattr__`, `__getitem__`, `__iter__`, `__len__`, `__dir__`, `uniques`,
  `save`, `get_surf`, `get_xfm`, `get_mask`, `get_overlay`, `prepend` all have zero
  docstrings** except `append` (one line) and `from_file` (fully documented). This is the
  least-documented class among everything covered in this module.
- **Attribute-style access (`dataset.somename`) is a core, load-bearing feature
  (`__getattr__`) with no documentation at all** — a user must discover by trial that
  `Dataset(foo=vol)['foo']` and `Dataset(foo=vol).foo` are equivalent.
- **Iteration order is non-obvious and undocumented**: `__iter__` yields `(name, view)`
  pairs sorted by `view.priority` (ascending), not by insertion order or alphabetically —
  this matters for anything that assumes dict-like insertion-order iteration.
- **`save(filename=None, pack=False)` has no docstring at all**, despite non-trivial
  behavior: `filename=None` reuses a previously-opened `self.h5` (raises `ValueError` if
  none exists yet); `pack=True` additionally bundles each unique subject's ROI SVG, surface
  geometry (`get_surf`), transform matrices, and any string-named masks directly into the
  HDF5 file, making it self-contained/portable (loadable on a machine without that subject
  registered in its pycortex database) — none of this is mentioned.
- **`get_surf`, `get_xfm`, `get_mask`, `get_overlay` all look like they call into the
  pycortex database (`cortex.db`) but actually only work on `Dataset` instances that were
  loaded from a "packed" HDF5 file** (`pack=True` in `save`, or loaded via `from_file` from
  such a file) — they read from `self.h5['subjects'][...]`, not the live pycortex database,
  and raise `IOError` if the relevant data wasn't packed in. This is a significant, easily
  misunderstood distinction (these look like — and are named like — `cortex.db`'s own
  `get_surf`/`get_xfm`/`get_mask`/`get_overlay`, but are a completely separate,
  file-backed implementation) that is undocumented anywhere.
- **`get_overlay`'s `type` parameter only actually supports `type='rois'`** — passing
  anything else raises `TypeError('Unknown overlay type')` — the signature accepts
  arbitrary `**kwargs` and a `type` default of `'rois'` that reads as more general-purpose
  than it is.
- **`from_file`'s `subject` parameter docstring is decent** but doesn't mention that
  loading also has silent-failure paths: a per-view load failure inside the "views
  generated by pycortex" loop is caught and just printed via `traceback.print_exc()`
  (not raised) — a corrupted/incompatible view in a `.hdf` file will be silently skipped
  (with a traceback printed to stderr) rather than causing `from_file` to fail, which could
  surprise a caller expecting all views to load or an exception to be raised.
- **No Returns section stating `append`'s return type is `self`** (enabling
  `Dataset().append(a=1).append(b=2)`-style chaining) — this is inferable from the `-> "Dataset"`
  return but isn't called out in prose.
- **No Raises section anywhere.**
- **No Examples section** on the class itself (only `Dataset.from_file`'s docstring
  parameters are documented; no usage example for constructing/using a `Dataset` at all).
- **`prepend(prefix)` docstring says "Adds the given prefix to the name of every data object
  and returns a new Dataset"** — accurate, but doesn't mention this iterates via `self`
  (i.e. uses the priority-sorted order from `__iter__`), which is irrelevant to correctness
  but worth knowing if a caller relies on dict ordering downstream.

## Fixed documentation

### Summary
Wrapper for multiple data objects — a named collection of `Dataview`s, used to bundle
related data layers for saving to disk or passing to `cortex.webshow`.

### Parameters (`__init__`)
- **\*\*kwargs** : `Dataview`, dict, str, tuple, or `Dataset`
    Each keyword names one entry. A `Dataview` is stored directly; a `dict` or another
    `Dataset` is merged in (flattened — its own keys become view names, not the outer
    kwarg name); a `str` is loaded as an `.hdf` file path via `Dataset.from_file` and
    merged in; a `tuple` is normalized via `cortex.dataset.views.normalize` (2-tuple →
    `Vertex`, 3-tuple → `Volume` or, for `uint8` data, `VolumeRGB`).

### Returns
N/A for `__init__`.

### Raises
- `ValueError` — an unrecognized value type is passed for some kwarg (message: `"Unknown
  input {name}={value!r}"`).
- `TypeError` (from the underlying `normalize` calls) — malformed tuple length, etc.

### Public methods and properties
- **`.append(**kwargs)`** → `Dataset` (`self`) — add more named views, using the same
  normalization rules as `__init__`. Returns `self`, enabling method chaining. Raises
  `ValueError` on an unrecognized value type, same as `__init__`.
- **`.views`** (attribute) : `dict[str, Dataview]` — the underlying name→view mapping.
  Direct dict access/mutation is possible but bypasses the type-normalization `append`
  performs.
- **Attribute access (`dataset.name`)** — equivalent to `dataset.views['name']` (via
  `__getattr__`); falls back to raising `AttributeError` if `name` isn't a real attribute
  or a view name.
- **Item access (`dataset['name']`)** — equivalent, via `__getitem__`; raises `KeyError`
  (not `AttributeError`) for a missing name, unlike attribute access.
- **Iteration (`for name, view in dataset:`)** — yields `(name, view)` pairs **sorted by
  `view.priority` ascending**, not insertion order.
- **`len(dataset)`** → int — number of views.
- **`dir(dataset)`** → list of str — instance attributes plus view names (supports
  tab-completion of view names in interactive use).
- **`.from_file(filename, subject=None)`** (classmethod) → `Dataset` — load from an `.hdf`
  file. `subject=None` uses whatever subject name(s) were saved in the file; pass an
  explicit `subject` to remap all loaded views onto a different (e.g. renamed) subject in
  your current pycortex database. Per-view load failures during the "views" section are
  caught and printed (via `traceback.print_exc()`) rather than raised — a partially
  corrupted file loads whatever views it can, silently dropping the rest. A `FileNotFoundError`
  encountered while resolving a subject is instead re-raised (after printing guidance about
  using the `subject` kwarg).
- **`.uniques(collapse=False)`** → set of `BrainData`/`Dataview` objects — the set of
  distinct underlying data objects referenced across all views (e.g. shared channels in RGB
  or 2D views are only counted once). `collapse` is forwarded to each view's own
  `.uniques()`.
- **`.save(filename=None, pack=False)`** — write all views to an HDF5 file.
  `filename=None` reuses a previously-associated file handle (`self.h5`, set by a prior
  `save(filename=...)` or by `from_file`); raises `ValueError` if there is none. `pack=True`
  additionally embeds each referenced subject's ROI SVG, surface geometry, transform
  matrices, and any string-named masks directly into the file (via `_pack_subjs`/
  `_pack_xfms`/`_pack_masks`), producing a self-contained file loadable without a local
  pycortex database registration for that subject. Flushes the HDF5 file before returning.
- **`.get_surf(subject, type, hemi='both', merge=False, nudge=False)`**,
  **`.get_xfm(subject, xfmname)`**, **`.get_mask(subject, xfmname, maskname)`**,
  **`.get_overlay(subject, type='rois', **kwargs)`** — read surface geometry / transform /
  mask / ROI-overlay data **from this Dataset's own packed HDF5 contents** (`self.h5`), not
  from the live pycortex database. Only work if the `Dataset` was saved with `pack=True` (or
  loaded from such a file) and contains the requested subject's packed data; raise
  `IOError` otherwise. `get_overlay` only supports `type='rois'` (any other value raises
  `TypeError('Unknown overlay type')`) and returns a `tempfile.NamedTemporaryFile` containing
  the ROI SVG XML, not a parsed overlay object.
- **`.prepend(prefix)`** → `Dataset` — a **new** `Dataset` with `prefix` prepended to every
  view name (does not mutate `self`).

### Notes
- No FreeSurfer/FSL/GUI dependency for in-memory use.
- `pack=True` (`save`) performs meaningful disk I/O and pycortex-database reads for every
  unique subject/transform/mask referenced — can be slow for many/large subjects, but
  produces a portable, self-contained file.
- `get_surf`/`get_xfm`/`get_mask`/`get_overlay` are easy to confuse with the
  similarly-named `cortex.db.get_surf`/`get_xfm`/`get_mask`/`get_overlay` methods on
  `cortex.database.Database` — the `Dataset` versions only ever read from this object's own
  packed HDF5 contents.
- Mutability: `.append` mutates `self.views` in place (and also returns `self`); `.prepend`
  does not mutate — it returns a new `Dataset`.

### Example
```python
import numpy as np
import cortex

subject = "S1"
xfm = "fullhead"
shape = cortex.db.get_xfm(subject, xfm).shape

vol1 = cortex.Volume(np.random.randn(*shape), subject, xfm, description="condition A")
vol2 = cortex.Volume(np.random.randn(*shape), subject, xfm, description="condition B")

ds = cortex.Dataset(condA=vol1, condB=vol2)
ds.append(condC=cortex.Volume.random(subject, xfm))

# Attribute-style and dict-style access are equivalent:
assert ds.condA is ds["condA"]

# Iterate views (sorted by priority):
for name, view in ds:
    print(name, view)

# Save a self-contained, portable copy (embeds subject geometry/transform/masks):
ds.save("example_dataset.hdf", pack=True)

# Reload elsewhere, even without `subject` registered locally:
ds_reloaded = cortex.Dataset.from_file("example_dataset.hdf")
```

## Confidence / open questions
- The claim that `dict`/`str`/nested-`Dataset` kwargs "flatten" (discarding the outer kwarg
  name in favor of the nested object's own view names) is based on reading `append`'s
  `elif isinstance(norm, Dataset): self.views.update(norm.views)` branch
  (`dataset.py:37-38`) — confirmed by static reading, not execution.
- Did not execute `save(pack=True)` end-to-end against a real pycortex database in this
  pass to confirm exact file layout/size implications — described from source reading of
  `_pack_subjs`/`_pack_xfms`/`_pack_masks` only.
- **Recommendation for maintainers:** this class has the thinnest docstring coverage found
  across the whole `cortex.dataset` module — almost every method besides `from_file` has no
  docstring at all. Priority additions: document the `**kwargs` normalization rules on
  `__init__`/`append`; document that `get_surf`/`get_xfm`/`get_mask`/`get_overlay` operate
  on packed HDF5 contents only (easily confused with `cortex.db`'s same-named methods);
  document `save`'s `pack` behavior and its `ValueError` when no filename is available.
